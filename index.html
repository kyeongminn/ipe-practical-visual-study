실선 + 삼각형
Generalization

의존 관계

점선 + 열린 화살촉
Dependency

인자·지역 변수·메서드 호출 등으로 다른 요소를 사용한다.

실체화 관계

점선 + 삼각형
Realization

인터페이스 등 명세의 계약을 실제로 구현한다.

구분 포인트마름모는 전체에 붙이고, 빈 삼각형은 부모·인터페이스를 향한다. 화살표가 없는 연관선은 양방향 탐색을 확정한다는 뜻이 아니라, 탐색 방향을 생략한 표기일 수 있다.

성형 / 스타형

Star

중앙 허브·스위치에 연결. 개별 링크 장애는 국소적이지만 중앙 장비 장애의 영향이 큼.

링형

Ring

이웃 노드끼리 고리로 연결. 단일 링은 단절에 취약하며 이중 링 등으로 보완.

버스형

Bus

하나의 공유 회선에 연결. 백본 단절의 영향이 크며 전통적 공유 매체에서 충돌 가능.

트리형 / 계층형

Tree

상위–하위의 계층 구조. 확장과 관리가 쉽지만 상위 연결 장애가 하위에 영향.

망형 / 메시형

Mesh

여러 경로로 연결하여 우회·중복성 확보. 완전 망형의 링크 수 = n(n−1)/2.

혼합형

B. 기초 경로와 순환 복잡도

독립 경로 ① · 1 → 2 → 3 → 5

F. 엣지 케이스 / 코너 케이스

먼저 분류엣지·코너 케이스는 테스트할 상황을 부르는 말이다. 화이트박스의 독립된 공식 기법 목록에 추가하는 항목은 아니다. 명세의 경계값 분석으로도, 코드의 분기·조건·루프 분석으로도 이런 사례를 찾을 수 있다.

엣지 케이스

Edge case · 경계·극단·드문 상황

보통 입력과 달리 경계나 극단 등 특수한 조건에서 동작을 확인하는 사례. 빈 목록, 원소 1개, 최대 길이 등이 예다. 여기서는 한 입력 축의 경계를 움직이고 다른 축은 보통 값으로 둔다.

한 축 예시: 항목 수 n=0, 재시도 한도 r=1

코너 케이스

Corner case · 여러 경계 조건의 결합

둘 이상의 경계 조건이 동시에 겹치는 상황을 뜻하는 구분으로 설명한다. 각 조건을 따로 시험했을 때와 결합했을 때의 동작이 달라질 수 있다.

두 축 예시: 항목 수 n=0 + 재시도 한도 r=0

용어 사용 범위는 문맥에 따라 다르다. 이 예제에서는 “한 축의 경계”와 “여러 경계의 결합”을 구분한다. 경계 밖 입력은 명세에서 정한 오류 처리를 별도로 확인한다. 수직선의 간격과 격자의 눈금은 축약했다.

사례입력 (n, r)확인할 것

엣지 · r의 최솟값(20, 0)재시도를 하지 않는 조건

코너 · 두 최댓값(100, 3)최대 항목 수와 최대 재시도 한도의 결합
범위 밖 · 오류 처리(101, 1) · (20, −1)명세에 정한 거부·오류 응답

G. 화이트박스와 연결 · 숨어 있는 결합 분기 찾기

def classify(n, r):
    # n: 항목 수 0~100 / r: 재시도 한도 0~3
    if not (0 <= n <= 100 and 0 <= r <= 3):
        return "INVALID"
    if n == 0 and r == 0:
        return "EMPTY_NO_RETRY"
    if n == 0:
        return "EMPTY"
    if r == 0:
        return "NO_RETRY"
    return "PROCESS"

각 경계만 검사하면 놓칠 수 있다

(0, 1) → EMPTY
(20, 0) → NO_RETRY

두 엣지 테스트에서 개별 조건을 각각 참으로 만들었어도 n==0 AND r==0의 참 분기는 아직 실행하지 않았다.

(0, 0) → EMPTY_NO_RETRY

코너 입력을 추가하여 결합 조건이 참인 경로를 실행한다. 이것만으로 전체 분기·조건 커버리지가 100%가 된다고 단정할 수는 없다.

반복문이 있다면 n=0·1·최대 부근도 함께 확인한다. 코드 예제는 분기 설명에 집중한 축약 예시이며 실제 반복 처리는 생략했다.

같은 입력, 다른 설계 근거명세의 0~100 범위로 -1·0·1·99·100·101을 고름 → 경계값 분석(블랙박스).

H. 블랙박스 테스트 기법

설계 근거명세·요구사항의 입력과 기대 출력을 기준으로 사례를 설계한다. 내부 코드를 몰라도 설계할 수 있으며, 정상 입력뿐 아니라 잘못된 입력의 기대 오류 처리도 포함한다.

동치 분할 검사 · 동등 분할

Equivalence Partitioning · EP

같은 방식으로 처리될 것으로 예상되는 입력을 동치 그룹으로 나누고 각 그룹에서 대표값을 선택한다. 유효 그룹과 무효 그룹을 모두 살핀다.

나이 18~60 허용 → 10 / 35 / 70으로 그룹 대표

경계값 분석

Boundary Value Analysis · BVA

순서가 있는 입력 범위의 경계와 그 이웃에 집중한다. 예를 들어 정수 나이 18~60은 17·18·19와 59·60·61을 살핀다.

동치 분할 = 그룹 대표 / 경계값 = 경계 주변

원인–효과 그래프 검사

Cause–Effect Graphing

입력 조건인 원인과 출력인 효과의 논리 관계를 그래프로 표현하고 테스트 조합을 선정한다. 필요하면 결정 테이블로 정리한다.

원인·조건 → AND / OR / NOT → 효과·출력

오류 예측 검사

Error Guessing

경험과 과거 결함을 바탕으로 오류가 날 만한 사례를 예상한다. 필수값 누락, 중복 클릭, 특수문자 등에서 명세에 맞는 처리를 확인한다.

과거 오류·경험으로 취약 사례 예상

비교 검사

Comparison Testing

같은 명세를 구현한 여러 버전에 동일한 테스트 자료를 주고 결과를 비교한다. 차이가 나면 원인을 조사하며, 결과가 같아도 모두 옳다는 증명은 아니다.

여러 버전 + 동일 입력 + 출력 비교

위 다섯 기법은 정보처리기사 수험서에서 블랙박스와 함께 다루는 대표 항목이다. ISTQB CTFL에서는 오류 예측을 경험 기반 기법으로 별도 분류한다. 문제에서 사용하는 분류 문맥을 확인하자.

I. 함께 알아둘 명세 기반 기법

결정 테이블 테스트

Decision Table Testing

여러 조건의 조합과 그에 따른 결과를 표로 정리한다. 이 예시는 회원 AND 5만원 이상일 때만 무료배송이다.

조건 조합 → 규칙 열 → 기대 결과

소프트웨어 테스트의 7가지 원리

테스트를 많이 하는 것과 올바르게 하는 것은 다릅니다.

PRINCIPLE 01

결함의 존재를 보여준다

Testing shows the presence of defects

결함은 발견할 수 있지만 결함이 전혀 없음을 증명할 수는 없다.

발견 0건 ≠ 결함 0개
PRINCIPLE 02

완벽한 테스팅은 불가능하다

Exhaustive testing is impossible

모든 입력·경로·환경의 조합을 검사하기는 어렵다. 위험·우선순위로 집중한다.

전수 검사 대신 우선순위
PRINCIPLE 03

테스팅은 초기에 시작한다

Early testing saves time and money

요구사항·설계부터 검토하여 뒤늦은 수정과 재작업을 줄인다.

일찍 발견 → 재작업 감소
PRINCIPLE 04

결함은 집중된다

Defects cluster together

적은 수의 모듈에 많은 결함이 모이는 경향. 결함 이력·위험을 참고한다.

파레토: 소수 영역에 다수 결함
PRINCIPLE 05

살충제 패러독스

Tests wear out

같은 테스트만 반복하면 새 결함 발견 효과가 줄어든다. 사례·데이터를 갱신한다.

회귀 테스트는 유지 + 새 사례 보강
PRINCIPLE 06

테스팅은 정황에 의존한다

Testing is context dependent

안전 제어·쇼핑몰 등 제품과 위험에 따라 테스트 전략이 달라진다.

목적·환경에 맞는 테스트
PRINCIPLE 07

오류 부재의 궤변

Absence-of-defects fallacy

명세상 결함을 고쳐도 사용자에게 쓸모없는 제품이면 성공이라 할 수 없다.

결함 제거 + 사용자 요구 충족
구분 포인트한 줄로 연결: 결함을 찾되 → 전부 검사할 수 없으니 → 일찍 시작하고 → 결함이 모인 곳에 집중하며 → 테스트를 갱신하고 → 상황에 맞게 검사하여 → 사용자에게 필요한 제품인지 확인한다.

수험서의 “살충제 패러독스”는 ISTQB CTFL 4.0.1에서 “Tests wear out”으로 설명한다. 파레토의 80/20은 경향을 기억하는 표현이며 모든 프로젝트에 정확히 적용되는 법칙은 아니다.

기밀성

C
Confidentiality
누가 볼 수 있는가?

인가된 대상만 정보를 열람하도록 하고, 허가되지 않은 접근·공개를 막는다.

침해 예시
고객의 개인정보가 외부로 새어나감

보호 수단
암호화 · 인증과 접근 통제 · 최소 권한

무결성

I
Integrity
내용을 믿을 수 있는가?

정보의 부적절한 변경·파괴를 막고 정확성과 완전성을 지킨다. 정당한 권한에 따른 수정까지 금지하는 뜻은 아니다.

침해 예시
송금액이나 성적이 허가 없이 변경됨

보호 수단
MAC · 전자서명 · 변경 권한 통제 · 신뢰된 기준 해시 비교

가용성

A
Availability
필요할 때 쓸 수 있는가?

인가된 사용자가 필요한 때 정보와 시스템에 적시에 안정적으로 접근하고 사용할 수 있게 한다.

침해 예시
DDoS·장애·정전으로 정상 이용이 막힘

보호 수단
이중화 · 장애 전환 · 백업·복구 · DDoS 대응

기밀성 ≠ 무결성

읽지 못하게 막는 것과, 내용이 바뀌지 않았는지 확인하는 것은 별개다. 암호화만으로 무결성이 자동 보장되지는 않는다.

AS 내부·외부와 거리 벡터·링크 상태·경로 벡터를 나눠 기억하기

먼저 구분라우팅은 목적지까지의 경로를 정하는 일. 정적 라우팅은 관리자가 경로를 설정하고, 동적 라우팅은 프로토콜로 정보를 교환하여 경로를 갱신한다.

1. 사용 범위 · AS 안인가, AS 사이인가?

IGP · 내부 라우팅

  • 거리 벡터RIP · IGRP
  • 개선된 거리 벡터EIGRP · 수험서에서 하이브리드로도 분류

2. 프로토콜별 핵심 특징

RIP

Routing Information Protocol

거리 벡터 · IGP
목적지까지 거치는 홉 수를 기준으로 선택. 최대 유효 값은 15, 16은 도달 불가.

RIP = 거리 벡터 + Bellman–Ford + 15홉

OSPF

Open Shortest Path First

링크 상태 · IGP
링크 상태를 공유하고 최단 경로를 계산. 영역(Area) 단위로 나눠 구성할 수 있다.

OSPF = 링크 상태 + Dijkstra + 비용

BGP

Border Gateway Protocol

경로 벡터 · 외부 라우팅
AS 경로 등 속성과 정책으로 경로를 선택. TCP 179번 포트로 피어 간 정보를 교환한다.

BGP = AS 사이 + 경로 벡터 + 정책

EIGRP

Enhanced Interior Gateway Routing Protocol

개선된 거리 벡터 · IGP
거리 벡터 기반으로 빠른 수렴과 루프 없는 경로 계산을 제공. 수험서에서는 하이브리드라는 표현도 사용한다.

EIGRP = DUAL · 단순히 링크 상태로 외우지 않기

IS-IS

Intermediate System to Intermediate System

링크 상태 · IGP
OSPF처럼 링크 상태와 최단 경로 계산을 이용하는 내부 라우팅 프로토콜.

OSPF와 IS-IS = 링크 상태

IGRP

Interior Gateway Routing Protocol

거리 벡터 · IGP
대역폭·지연 등을 고려하는 Cisco의 과거 프로토콜. EIGRP와 이름을 구분한다.

IGRP = 과거 방식 / EIGRP = 개선된 방식

3. 홉 수가 적은 길과 비용이 낮은 길

RIP · 적은 홉 수

위쪽 경로는 2홉, 아래쪽 경로는 3홉. RIP는 홉 수가 적은 위쪽을 선택한다.

OSPF · 낮은 비용 합

숫자를 OSPF 링크 비용으로 놓으면 위쪽은 9+9=18, 아래쪽은 1+1+1=3. 아래쪽을 선택한다.

이해를 위한 단순한 비용 예시다. 파란 선은 선택 경로이며 RIP는 그림의 비용값 대신 홉 수를 센다.

BGP는 다르게BGP는 단순히 홉 수가 가장 적거나 IGP 비용이 가장 낮은 길만 고르는 방식이 아니다. AS_PATH 등 여러 경로 속성과 운영 정책을 함께 고려한다.

3. 커밋은 어디에 기록될까?

SVN · 서버에 기록

commit은 중앙 서버 저장소에 변경을 반영한다. 서버 연결이 끊겨도 작업본 편집은 가능하지만 서버에 커밋할 수 없다.

Git · 로컬 기록 후 공유

commit은 로컬 저장소에 기록한다. push는 로컬 커밋을 원격으로 보낸다. 원격 연결 없이도 로컬 커밋과 이력 조회가 가능하다.

헷갈림 방지작업본 ≠ 이력 저장소. 파일이 내 PC에 있다고 모두 분산형은 아니다. Git의 commit ≠ push이며, GitHub는 Git 저장소를 호스팅하는 서비스다. 분산형도 원격 서버를 사용할 수 있고 병합 충돌이 발생할 수 있다.

2. 대칭키 · 대표 블록 암호 7종

한 번에 고정 크기의 블록을 처리한다. 시험 학습용 대표 알고리즘을 정리했으며, 아래 숫자는 비트 단위다. 블록 크기와 키 길이를 따로 읽는다.

DES

Data Encryption Standard

Feistel 구조 · 16라운드. DES의 실제 암호 키는 56비트이며 패리티를 포함한 표현은 64비트다.

DES = 블록 64 / 키 56

3DES

Triple DES · TDEA

DES 연산을 세 번 조합한 방식. DES보다 키를 확장했지만 블록 크기는 여전히 64비트다.

3DES = DES 세 번 / 블록은 64

AES

Advanced Encryption Standard

Rijndael을 기반으로 한 SPN 계열 블록 암호. AES-128·192·256의 숫자는 키 길이이며 블록 크기는 모두 128비트다.

AES = 블록 128 / 키 128·192·256

SEED

국산 블록 암호

KISA에서 개발. 16라운드 Feistel 구조로, 블록과 키의 길이가 모두 128비트다.

SEED = 128 / 128 / Feistel

ARIA

국산 범용 블록 암호

Involutional SPN 구조. 키 길이에 따라 12·14·16라운드를 수행한다.

ARIA = 128 / 128·192·256 / SPN

IDEA

International Data Encryption Algorithm

스위스에서 개발한 PES를 개선한 알고리즘. 64비트 블록과 128비트 키를 연결해 기억한다.

IDEA = 블록 64 / 키 128

Skipjack

NSA · Clipper Chip

미국 NSA에서 개발했으며 Clipper Chip과 연결되는 과거 블록 암호다.

Skipjack = 블록 64 / 키 80 / Clipper Chip

3. 대칭키 · 스트림 암호

RC4

Rivest Cipher 4

키 스트림을 만들어 평문과 XOR하는 스트림 암호. 블록 암호인 AES·SEED와 구분한다.

RC4 → 대칭키 → 스트림

ChaCha20

스트림 암호 · 추가 비교

256비트 키를 사용하는 스트림 암호. ARX 연산(덧셈·회전·XOR)을 사용한다.

ChaCha20도 대칭키 · 스트림

DES·3DES·RC4·Skipjack 등 과거 알고리즘도 시험 분류 학습을 위해 포함했다. 목록에 있다는 사실이 현재 시스템의 채택을 권장한다는 뜻은 아니다.

4. 비대칭키 계열 · 이름과 역할

RSA

Rivest–Shamir–Adleman

큰 정수의 소인수분해 문제와 연결한다. 암호화와 전자서명에 각각 적절한 방식으로 사용한다.

RSA = 소인수분해

ElGamal

이산 로그 계열

이산 로그 계열의 수학적 문제에 기반한 공개키 암호화 방식. 같은 이름의 서명 방식과는 절차를 구분한다.

ElGamal = 이산 로그 계열

ECC

Elliptic Curve Cryptography

타원곡선 이산 로그 문제를 이용하는 공개키 암호 기술 계열. ECDH는 키 합의, ECDSA는 서명에 사용한다.

ECC = 타원곡선 / ECDH ≠ ECDSA

DH

Diffie–Hellman

통신 당사자가 공유 비밀을 합의하는 공개키 기법. 실제 메시지를 직접 암·복호화하는 알고리즘과 구분한다.

DH = 키 합의 / ECDH = 타원곡선 기반

DSA · ECDSA

Digital Signature Algorithm

DSA는 전자서명 알고리즘, ECDSA는 타원곡선 기반 서명 알고리즘. 메시지 암호화용이 아니다.

DSA·ECDSA = 서명 생성·검증
공개키 계열 ≠ 모두 암호화RSA·ElGamal은 암호화, DH·ECDH는 키 합의, DSA·ECDSA는 서명으로 구분한다. ECC는 여러 구체적 방식의 기반이 되는 계열명이다. SHA-256 등 해시는 별도의 단방향 요약 함수다.

용어: 수험서의 “개인키 암호화”는 대칭키를 뜻하기도 한다. 공개키와 짝인 개인키라는 의미와 문맥으로 구분한다.

DDoS · 분산 서비스 거부

스니핑

Sniffing

통신 중인 패킷을 몰래 관찰·도청한다. 암호화된 패킷을 수집했다고 내용을 바로 해독할 수 있는 것은 아니다.

스푸핑

Spoofing

신원이나 주소 정보를 정상 대상처럼 속이는 행위. IP·ARP·DNS 등 위장 대상에 따라 구분한다.

Session Hijacking = 세션 가로채기

C. 웹 · 입력 처리 · 인증 공격

SQL 삽입

SQL Injection · SQLi

입력이 SQL 명령 구조에 섞여 DB 조회·변조나 인증 우회를 유발한다. 핵심 구분은 “데이터가 명령으로 해석되는가”이다.

SQLi = 데이터가 SQL 명령으로 해석

크로스 사이트 스크립팅

Cross-Site Scripting · XSS

웹 페이지나 DOM 처리의 결함으로 피해자 브라우저에서 스크립트가 실행된다. 저장형·반사형·DOM 기반 등이 있다.

XSS = 브라우저의 스크립트 실행

크로스 사이트 요청 위조

Cross-Site Request Forgery · CSRF

로그인된 사용자의 브라우저가 원치 않는 요청을 보내게 유도한다. 브라우저가 자동 전송하는 인증 정보와 서버의 요청 검증 부족을 악용한다.

CSRF = 인증된 사용자의 요청 위조

D. 사람을 속이거나 표적을 노리는 공격

피싱

Phishing

정상 기관·사람인 것처럼 속여 비밀번호 등 민감 정보나 행동을 유도한다. 이메일·가짜 사이트 등 여러 매체를 이용한다.

Phishing = 신뢰를 미끼로 정보 낚기

스피어 피싱

Spear Phishing

특정 대상을 조사하고 그 대상에 맞춘 내용으로 속이는 표적형 피싱. 단순히 발송 횟수가 많다는 뜻이 아니다.

Spear = 표적을 정한 피싱

스토리지 연결 방식

서버와 저장장치를 직접 잇는가, 일반 네트워크로 잇는가, 전용 네트워크로 잇는가

먼저 구분스토리지 연결 방식은 서버와 저장장치를 잇는 경로로 나눈다. 직접 연결하면 DAS, 일반 네트워크(LAN)에 붙이면 NAS, 저장장치만을 위한 전용 네트워크를 따로 깔면 SAN이다. 핵심 기준은 연결 경로와 여러 서버의 공유 가능 여부다.

1. 연결 구조를 그림으로 보기

DAS

Direct Attached Storage

직접 연결 · 공유 불가
저장장치를 서버의 호스트 버스 어댑터(HBA)에 직접 연결한다. 속도가 빠르고 구축이 쉬우며 저렴하지만, 다른 서버와 공유할 수 없고 확장성이 낮다.

DAS = Direct · 직접 연결 · 공유 불가

NAS

Network Attached Storage

네트워크 연결 · 파일 단위 공유
서버와 저장장치를 일반 네트워크(이더넷)로 연결한다. 별도의 파일 관리 기능이 있는 NAS 스토리지가 저장장치를 직접 관리한다. 접속이 늘면 네트워크 부하로 성능이 떨어질 수 있다.

NAS = Network Attached · LAN · 파일 공유

SAN

Storage Area Network

전용 네트워크 · 블록 단위 공유
서버와 저장장치만 잇는 전용 네트워크를 따로 구성한다. 광 채널(FC) 스위치를 사용하며, DAS의 빠른 처리와 NAS의 공유 장점을 합쳤다. 별도의 망을 구축해야 해서 비용이 많이 든다.

2. IPsec · AH / ESP / IKE

AH · Authentication Header

인증 · 무결성

데이터 출처 인증과 무결성, 재전송 공격 방지 등에 쓰입니다. 내용 암호화에 의한 기밀성은 제공하지 않습니다.

ESP · Encapsulating Security Payload

암호화 + 인증·무결성

기밀성을 제공할 수 있고 인증·무결성도 지원합니다. 실제 제공 기능은 설정에 따르므로 “ESP는 암호화만 한다”로 외우지 마세요.

IKE · Internet Key Exchange

인증 · 키 합의 · SA 관리

통신 상대를 인증하고 사용할 알고리즘·키와 SA(Security Association, 보안 연관)를 협상·관리합니다. AH·ESP가 사용할 보호 조건을 마련합니다.

전송 모드 · Transport

주로 호스트 간 통신에서 사용합니다. 그림은 보호 범위를 이해하기 위한 ESP 축약도입니다.

터널 모드 · Tunnel

VPN 게이트웨이 간 연결 등에 사용합니다. 원래 패킷 바깥에 새 IP 헤더가 붙습니다.

3. TLS와 응용 보안 프로토콜

TLS · 통신 경로 보호

TLS의 핸드셰이크로 상대를 인증하고 키를 합의한 뒤, 레코드 계층에서 데이터를 보호합니다. 일반적으로 서버 인증을 하며 클라이언트 인증도 가능합니다.

HTTPS vs S-HTTP

HTTPS = HTTP 통신에 TLS 적용
S-HTTP = HTTP 메시지 단위 보호

HTTPS는 보호된 채널로 웹 통신을 전달합니다. S-HTTP는 별도의 메시지 중심 규약입니다. 두 이름을 같은 뜻으로 쓰지 않습니다.

포트 암기: HTTPS 기본 443 / SSH 통상 22. SSL/TLS 자체에 모든 용도가 공유하는 단일 포트가 있는 것은 아닙니다.

SSH

L7 · 응용
암호화된 원격 접속

보안 원격 로그인·명령 실행 등에 사용한다. 통상 TCP 22번을 쓰며 SFTP도 SSH 기반이다.

S/MIME

L7 · 응용
인증서 기반 메일 보안

MIME 메시지에 전자서명·암호화를 적용한다. X.509 인증서를 이용한다.

PGP

L7 · 응용
메일·파일 서명·암호화

공개키·대칭키 암호와 전자서명을 조합해 메시지·파일을 보호한다. OpenPGP가 공개 표준 형식이다.

메일 보안 구분S/MIME은 X.509 인증서 기반, PGP는 공개키·대칭키·서명을 조합한 메시지 보호로 기억합니다. HTTPS나 메일 전송 구간 TLS와 달리 메시지 자체를 암호화·서명할 수 있습니다.

4. 터널링과 암호화 구분

L2TP

3. 정렬을 세 묶음으로 외우기

O(n²) 묶음

평균
버블 · 선택 · 삽입 (+ 셸 O(n^1.5))

단순 비교 정렬. 입력이 두 배가 되면 시간은 네 배. 삽입은 거의 정렬된 입력에서 O(n), 선택은 항상 O(n²).

버블 정렬
인접한 두 값을 비교·교환하며 큰 값을 끝으로 보낸다. 교환이 없으면 멈추는 개선형은 최선 O(n).

선택 정렬
남은 구간에서 최솟값을 골라 앞과 교환한다. 입력이 이미 정렬되어 있어도 비교 횟수는 같다.

삽입 정렬
앞쪽의 정렬된 구간에 새 값을 끼워 넣는다. 거의 정렬된 입력에서는 O(n)에 가깝다.

셸 정렬
간격(gap)을 두고 삽입 정렬을 반복하며 간격을 줄인다. 수험서는 평균 O(n^1.5)로 표기한다.

O(n log n) 묶음

평균
퀵 · 합병 · 힙

비교 정렬의 평균 하한. 퀵은 최악 O(n²), 합병은 공간 O(n), 힙은 공간 O(1)이면서 항상 O(n log n).

퀵 정렬
피벗을 기준으로 작은 쪽·큰 쪽으로 분할한다. 평균은 가장 빠른 편이지만 피벗이 치우치면 최악 O(n²).

합병(병합) 정렬
반으로 나눈 뒤 정렬된 두 구간을 병합한다. 항상 O(n log n)이지만 병합용 추가 배열 O(n)이 필요하다.

힙 정렬
힙을 만들고 루트(최댓값)를 꺼내 재구성하기를 반복한다. 추가 공간 없이 항상 O(n log n).

분포 기반 묶음

선형
기수 · 계수

값을 비교하지 않고 자릿수·횟수로 배치. O(dn)·O(n+k)로 선형에 가깝지만 값의 범위에 의존.

기수 정렬
자릿수(d)마다 버킷에 분배·수집한다. 값을 비교하지 않는 정렬이며 k는 기수(10진수면 10).

계수 정렬
값의 등장 횟수를 센 뒤 누적합으로 자리를 정한다. 값의 범위 k가 n에 비해 작을 때 유리하다.
